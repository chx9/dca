# 美股数据源方案

> 实测日期：2026-11-02，测试机：本机（中国大陆网络，macOS）。
> 结论只写**当天真的连上了**的东西，没跑通的一律标注原因。

## 一、结论

| 源 | 要 key 吗 | 本机额度 | 今天实测 | 适合做什么 |
|---|---|---|---|---|
| **东方财富** | 否 | 无明确限额（请控制频率） | ✅ 三个接口全部可用 | **当前主源**：日线、最新报价、分红、拆股 |
| FMP (Financial Modeling Prep) | 是，`FMP_API_KEY` | 免费版 **250 次/天**、300 次/分 | ⚠️ 可连通，返回 401（本机未配 key） | 配好 key 后的主源：行情、分红、拆股、公司资料 |
| Alpha Vantage | 是，`ALPHAVANTAGE_API_KEY` | 免费版 **25 次/天** | ⚠️ 可连通，demo key 被拒 | 只做兜底，一天 25 次连补一天的红利都不够 |
| Yahoo Finance | 否 | — | ❌ 429 / 地区限制 | 不可用 |
| Stooq | 否 | — | ❌ 连接失败 | 不可用 |
| Nasdaq 官网 API | 否 | — | ⚠️ 仅覆盖纳斯达克上市标的，SCHD 返回 "not available" | 可选，覆盖不全 |

**一句话**：FMP 和 Alpha Vantage 都要 key，本机现在**都没有配**，所以这两家一条数据都拿不到。
东方财富免 key、境内直连、三只标的全覆盖，今天已经全部跑通，建议作为现阶段的主源，并在图上标明「数据来源 东方财富」。

## 二、东方财富（当前可用）

### 1. 市场编号

| 标的 | secid | SECUCODE 后缀 |
|---|---|---|
| IQQ | `105.IQQ` | `IQQ.O` |
| BRK.B | `106.BRK_B`（代码里的点换成下划线） | `BRK_B.N` |
| SCHD | `107.SCHD` | `SCHD.A` |

- `105` 纳斯达克、`106` 纽交所、`107` NYSE Arca。**后缀和编号不是一回事**：`O` = 纳斯达克，`N` = 纽交所，`A` = Arca/AMEX。写错后缀只会返回「返回数据为空」，不报错，很容易误判。

### 2. 日线（历史行情）

```bash
curl "https://push2his.eastmoney.com/api/qt/stock/kline/get?\
secid=105.IQQ&fields1=f1,f2&fields2=f51,f52,f53,f54,f55,f56,f57&\
klt=101&fqt=1&beg=20261001&end=20261101"
```

- `klt=101` 日线，`fqt=1` 前复权（已按拆股/分红调整），`fqt=0` 不复权。
- 返回 `klines` 是逗号串：`日期,开,收,高,低,成交量,成交额`。
- 价格是**原始小数**（`23.360`），不是整数定点，直接用。
- 实测可回溯深度：QQQ 到 2001-01-02（6492 根）、BRK.B 到 2011-03-25、SCHD 到 2011-10-20。

### 3. 最新报价（批量）

```bash
curl "https://push2.eastmoney.com/api/qt/ulist.np/get?\
secids=105.IQQ,106.BRK_B,107.SCHD&ut=fa5fd1943c7b386f172d6893dbfba10b&\
fields=f12,f13,f14,f2,f3,f4,f18"
```

| 字段 | 含义 | 换算 |
|---|---|---|
| `f12` / `f14` | 代码 / 名称 | — |
| `f2` | 最新价 | **÷1000** |
| `f3` | 涨跌幅 % | **÷100** |
| `f4` | 涨跌额 | ÷1000 |
| `f18` | 昨收 | ÷1000 |

> 单只的快照接口 `push2.eastmoney.com/api/qt/stock/get` 在本机**连不上**（curl 返回 000），但同一台机器上批量接口 `ulist.np/get` 正常。取单只用批量接口传一个 secid 即可。

### 4. 分红

```bash
curl "https://datacenter.eastmoney.com/securities/api/data/v1/get?\
reportName=RPT_USF10_INFO_DIVIDEND&columns=ALL&\
filter=(SECUCODE%3D%22QQQ.O%22)&pageNumber=1&pageSize=200&\
sortColumns=EX_DIVIDEND_DATE&sortTypes=-1&source=SECURITIES&client=PC"
```

返回字段：`NOTICE_DATE` 公告日、`ASSIGN_TYPE` 类型（Cash）、`PLAN_EXPLAIN` 方案文字、
`EQUITY_RECORD_DATE` 股权登记日、`EX_DIVIDEND_DATE` 除息日、`BONUS_PAY_DATE` 派息日。
实测 QQQ 共 89 条，SCHD 20 页（约 200 条）。

⚠️ **没有数值型的每股金额**，金额藏在中文句子里：`"每1份派0.75143美元股息"`，得用正则抠出来。
抠出来之后要和 `ASSIGN_TYPE == "Cash"` 一起校验，遇到不认识的句式就记 `缺失`，**不要猜**。
BRK.B 不发股息，返回「返回数据为空」是**正常结果**，不是抓取失败 —— 但两种情况的 JSON 长得一模一样，代码里要靠「证券存在 + 该证券确实不分红」来区分，别把空数组当错误重试。

### 5. 拆股

同上的 `reportName=RPT_USF10_SH_SPLIT`，字段 `NOTICE_DATE / EX_DIVIDEND_DATE / EXPLAIN`。
三只标的当前都是空结果。

## 三、FMP（配好 key 后更省事）

免费版：**250 次/天**、300 次/分，官方文档列出的免费能力是 End of Day 历史行情 + Profile/参考数据，150+ 接口。
今天从本机能连通（`https://financialmodelingprep.com/api/v3/quote/QQQ` → HTTP 401，3.3 秒），说明**网络没问题，缺的只是 key**。

官方现行（stable）路径，已对照文档页核实：

| 用途 | 路径 | 参数 |
|---|---|---|
| 最新报价 | `/stable/quote` | `symbol=QQQ`（也支持 `symbol=QQQ,BRK-B,SCHD` 批量） |
| 历史日线 | `/stable/historical-price-eod/full` | `symbol=QQQ&from=2026-10-01&to=2026-10-30` |
| 分红 | `/stable/dividends` | `symbol=SCHD` |
| 拆股 | `/stable/splits` | `symbol=QQQ` |

- 主机是 `https://financialmodelingprep.com`，key 用 `apikey=` 或 `Authorization: Bearer`。
- 旧的 `api/v3/...` 路径也还在，但新代码建议直接写 stable。
- **符号写法**：FMP 用 `BRK-B`（连字符），东财用 `BRK_B`（下划线），两边都要维护映射，别混。
- 免费版能不能一次拉满 10 年，官方页面没写死，需要拿真 key 实测一次再定。

### 配 key

```bash
export FMP_API_KEY=xxxx        # 只放环境变量，写进 ~/.zshrc 也行
```

代码里**只从 `process.env.FMP_API_KEY` 读**，不落盘、不进日志、报错信息里要脱敏（打印 `sk-…abcd` 这种形式也不行，直接不打印）。

## 四、Alpha Vantage（兜底）

- 免费版 **25 次/天**（官网 Premium 页原文："standard API usage limit (25 API requests per day)"）。
- 三只标的、每天一次快照 = 3 次，加上补历史根本不够；只适合「某一天东财挂了，用它补当日收盘」。
- 用 `GLOBAL_QUOTE&symbol=QQQ`（快照）和 `TIME_SERIES_DAILY_ADJUSTED&symbol=QQQ&outputsize=full`（日线，含复权）。
- 按需求方规则：**换源就要标源**，Alpha Vantage 取到的点不能和东财的点混在同一条曲线里不说明。

## 五、已知的坑

1. **IQQ 是一只 2026-07-09 才上市的 ETF（iShares Nasdaq 100 ETF）**，东财只有 81 个交易日。
   做「十年定投」的回溯或基准对比时，别拿 QQQ 冒充 IQQ —— 要么明确写「参照 QQQ（非持仓标的）」，要么就显示缺失。
2. **跨市场交易日取交集**。三只标的分属 105/106/107，节假日不同（SCHD 是 ETF，BRK.B 是股票），
   画同一条横轴时必须取交集，否则某只停牌会把曲线画歪。`covers/fetch-quotes.mjs` 已经这么做了。
3. **不复权 / 前复权别混用**。分红和拆股会让不复权价格出现台阶。走势图用前复权（`fqt=1`）算涨跌幅才合理；
   但「历史成交价」要存**成交当日的实际价格**，那是复权数据给不了的，只能在定投那天记一笔。
4. **交易日 ≠ 自然日**。月末最后一天如果是周末，最新收盘要取「最后有报价的交易日」，并标明日期。

## 六、七张表分别从哪来

| 表 | 来源 | 说明 |
|---|---|---|
| `stock_quotes` | 东财 `ulist.np/get` → 有 key 时 FMP `/stable/quote` | 每日快照，带 `source` 和 `fetched_at` |
| `historical_prices` | 东财 `kline`（`fqt=1`）→ FMP `/stable/historical-price-eod/full` | 日线 OHLCV + 成交额 |
| `investment_transactions` | **手填**（`covers/issues/*.json` 或独立账本） | 任何接口都拿不到，**不得由行情推算** |
| `holdings_snapshots` | 由上面两张表算 | 股数 = 累计份额；市值 = 股数 × 当日收盘 |
| `dividends` | 东财 `RPT_USF10_INFO_DIVIDEND` → FMP `/stable/dividends` | 只做「应派」记录；**实到金额以券商对账单为准** |
| `monthly_reports` | 由上面几张表汇总 | 只汇总，不预测 |
| `data_logs` | 每次抓取的记录 | 源、接口、状态码、条数、耗时、是否缺失 |

## 七、建议的取数顺序

```
1. 读 FMP_API_KEY → 有就走 FMP（主源）
2. FMP 失败/额度用尽（250 次/天）→ 走东财（备源）
3. 东财再失败 → 返回 缺失/null，并在 data_logs 里记一条失败
4. 任何一条记录都带 source 字段，图/表上标源
```

- **不重试到死**：同一接口连续失败 2 次就放弃，落 `缺失`。
- **不补齐**：缺的那一天就是 null，不用前一天收盘价填、不插值、不按比例缩放。
- **不合并**：东财和 FMP 的数据不进同一条序列。真要混，另起一列并标注。

## 八、2026-11-02 晚补充实测

同一天下午再测，情况有变化，已据此给 `fetch-quotes.mjs` 加了兜底和缓存：

| 源 | 实测结果 |
|---|---|
| 东方财富 `push2his .../kline/get` | ❌ 连接建立后**空回复**（对方主动挂断）；加 `ut`、换编号子域、换 HTTP、换 push2 主机都不行。疑似按路径/IP 拒绝，未确认 |
| 东方财富 `push2 .../ulist.np/get`（批量报价） | ✅ 正常。说明东财是**按接口路径**拒绝，不是整站封 IP |
| 东方财富 `datacenter`（分红） | ✅ 正常 |
| **Nasdaq 官方 API** | ✅ `api.nasdaq.com/api/quote/<SYM>/historical?assetclass=etf|stocks&fromdate=&todate=&limit=`，免 key。三只标的都覆盖（SCHD 属 NYSE Arca 也能查），收盘价与东财一致（SCHD 35.78 / IQQ 23.36 / BRK.B 542.49，2026-10-30） |
| 腾讯 `usfqkline` | ⚠️ 只回最新 1 天，历史已不可用 |
| 新浪 `US_MinKService` | ❌ Service not valid |
| Stooq | ❌ 被 JS proof-of-work 反爬墙挡住 |
| Yahoo | ❌ 429 未变 |

**当前策略**：东财主源 → Nasdaq 兜底（同一次运行内东财失败一次就整体切换，不反复重试）。
`data/quotes-cache.json` 按标的缓存收盘价，每次只补「最新缓存日期之后」的交易日；
缓存里已有的日期不重抓、不覆盖，换源也不会让历史值漂移。

> Nasdaq 返回的是**不复权收盘价**。默认 30 天窗口里 SCHD 的除息日基本不在窗口内，差异可忽略；
> 若以后把窗口拉长到跨除息日，记得回到「前复权」口径或标注复权方式（见第五节第 3 条）。

## 九、下一步需要你决定的事

1. 要不要现在配 `FMP_API_KEY`？配了就能把 FMP 设为主源，250 次/天跑三只标的绰绰有余。
2. 10 年历史行情，是只取「持仓期间」，还是一开始就把三只的完整历史落库？（后者一次性约 3 次请求，东财一天就能拉完）
3. 分红要不要接进「累计收到现金」那一项？如果接，实到金额仍以券商对账单为准，接口只给「应派」。
